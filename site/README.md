# Radar — الموقع

صفحة الهبوط والصفحات القانونية والداشبورد. Next.js على **Vercel**.

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # الناتج في .next/
npm run typecheck
```

**مفيش `output: 'export'` تاني.** الموقع كان تصدير ثابت وهو على Firebase
Hosting، وللتركيبة دي عيب واحد مكانش ليه حل من جوّه: راوتر Next بيعمل prefetch
لمسار فيه نقطة، والتصدير بيكتب مجلد — فكل prefetch كان بيرجع 404 وكل تنقّل
بيقع على تحميل صفحة كامل. على Vercel رانتايم Next هو اللي بيرد، فالتنقّل من
جوّه المتصفح شغّال. كل الصفحات لسه بتتولّد وقت البناء (كلها client components
من غير بيانات سيرفر) — اللي اتغيّر هو مين بيقدّمها.

## PWA — الموقع بيتثبّت كتطبيق

الموقع تطبيق ويب تقدمي كامل: بيتثبّت على أندرويد وويندوز وماك ولينكس (Chrome/Edge)
وعلى آيفون وآيباد (Safari)، وبيفتح في نافذته لوحده من غير شريط عنوان.

| القطعة | مكانها | بتعمل إيه |
|---|---|---|
| الـ manifest | `app/manifest.ts` | راوت مش ملف ثابت، عشان الاسم والوصف والألوان يجوا من `lib/site.ts` وما يفرقوش عن الصفحات |
| الـ service worker | `public/sw.js` | أوفلاين + **شرط التثبيت نفسه** |
| التسجيل وزرار التثبيت | `components/pwa.tsx` | `<ServiceWorkerRegistrar />` في الـ layout، و`<InstallButton />` في الهيدرين |
| شاشة الأوفلاين | `app/offline/page.tsx` | اللي الـ SW بيقدّمه لما التنقّل يفشل ومفيش نسخة مخزّنة |
| الأيقونات | `tool/gen-pwa-icons.mjs` → `public/icons/` | `npm run icons` |

### الزرار مش بيظهر؟ ده مش باج بالضرورة

Chrome **مبيطلّعش** حدث `beforeinstallprompt` — اللي زرار «ثبّت التطبيق» مستنيه —
غير لما **كل** دول يتحققوا، ولو واحد ناقص مفيش أي رسالة خطأ في أي مكان، الزرار
ببساطة مبيظهرش:

- HTTPS (أو `localhost`)
- manifest فيه `name` و`short_name` و`start_url` و`display: standalone`
- أيقونتين على الأقل: **192 و512**
- service worker **مسجّل وفيه `fetch` handler**

وكمان مبيظهرش لو التطبيق **متثبّت أصلًا**، ولا في متصفح مضمّن (Electron وشبهه)،
ولا في iOS Safari أبدًا — التثبيت هناك من قائمة المشاركة وملهاش API. عشان كده
تعليمات الآيفون مكتوبة نص في الفوتر بدل زرار مش هيشتغل.

#### وفيه سبب خامس كان بيضيّع الزرار — واتقفل

Chrome بيطلق `beforeinstallprompt` أول ما يخلّص تقييم التثبيت، **ومش مستني
React**. لو الحدث وصل قبل ما `useEffect` بتاع `<InstallButton>` يركّب الـ
listener، الحدث بيضيع — مبيتعادش تاني، ومفيش API تطلبه بيه. النتيجة زرار مخفي
على صفحة كل شروطها سليمة، وده أسوأ نوع باج لأن كل المتهمين الواضحين بريئين.

الحل سكريبت مضمّن في `<head>` في `app/layout.tsx` (جنب سكريبت الثيم بالظبط،
ولنفس السبب — أي حاجة مؤجّلة بتيجي متأخرة):

```
window.__radarInstallPrompt   ← الحدث متخزّن هنا أول ما يوصل
'radar:installable'           ← إشارة للمكوّنات إنه وصل
```

`<InstallButton>` بيقرا المخزّن ده أول ما يتركّب وبيسمع الإشارة كمان، فبيوصل
لنفس الحالة سواء اتركّب قبل قرار المتصفح أو بعده. الضغطة بتفضّي المخزّن مش
الـ state بس، لأن الحدث بيتستخدم مرة واحدة وفيه زرارين (هيدر الموقع وشل
الداشبورد).

### الأيقونات — ليه تلاتة مش واحدة

`assets/logo.png` **مالوش قناة شفافية**: المربع المدوّر مرسوم على أركان سودة صريحة،
وجسمه نفسه `rgb(12,13,17)` — قريب من الأسود ومش هو. يعني أي محاولة تحطّه على خلفية
مسطّحة بتسيب خط: تطابق الجسم فالأركان السودة تبان أوتاد، تطابق الأركان فالمربع
المدوّر يبان لوح أفتح. **الاتنين اتجرّبوا والاتنين بانوا.**

فالنسخة الـ maskable بتستخرج الرمز الليموني نفسه بقناع لمعان وبترسمه على خلفية
مالية الكادر. ده مهم لأن أندرويد بيقصّ أي أيقونة `maskable` على شكل الـ launcher
وبيرمي اللي بره دايرة الـ 80% الوسطانية — تديله المصدر زي ما هو تطلّع أيقونة
مدوّرة مرتين.

و`app/apple-icon.png` بيتسطّح على نفس الخلفية، لأن iOS بيركّب أيقونة الشاشة
الرئيسية على **أسود** ومبيحترمش الألفا.

### الاختبار محليًا

`next dev` **مبيصلحش**: الـ SW بيرفض يسجّل نفسه بره الإنتاج عن قصد
(`components/pwa.tsx`) عشان مايخزّنش تشنكات تطوير بتختفي مع أول بناء.

```bash
npm --prefix site run build && npm --prefix site run start
```

بعدها في Chrome على `http://localhost:3000` (لوكال هوست بيتحسب secure context):

1. **DevTools → Application → Manifest** — لازم تلاقي الاسم والأيقونات، وفوق
   خالص سطر **Installability** يقول «Page is installable» من غير أخطاء.
2. **Application → Service Workers** — الحالة `activated and is running`،
   والـ Source `/sw.js`.
3. **Application → Cache Storage** — لازم تلاقي `radar-v1-shell` و`radar-v1-assets`.
4. **زرار التثبيت** — أيقونة في شريط العنوان، أو زرار «ثبّت التطبيق» في هيدر
   الموقع. لو مش ظاهر، ارجع لقايمة الشروط فوق.
5. **الأوفلاين** — Network → Offline، وبعدين حدّث صفحة زرتها قبل كده (لازم
   تشتغل) وصفحة عمرك ما فتحتها (لازم تطلّع «مفيش اتصال»).
6. **Lighthouse** — تبويب Lighthouse، اختار **Desktop** أو **Mobile** وشغّل.
   ملحوظة: Lighthouse شال تصنيف «PWA» المستقل من نسخة 12، فبقى الحكم على
   التثبيت في تبويب Application مش في تقرير Lighthouse — Lighthouse لسه مفيد
   للأداء وHTTPS وباقي التصنيفات.

**اللي `next start` مش بيعيد إنتاجه:** ترويسات `vercel.json`. يعني مفيش CSP
محليًا، والـ `worker-src 'self'` اللي فيها لازم يتشاف على النشر نفسه — لو الـ SW
اتمنع هتلاقي انتهاك CSP في الكونسول.

## قبل النشر — عيّن الدومين

**إجباري.** الدومين بيدخل في الروابط الأساسية (canonical) وملف السايت ماب
وصورة المشاركة، ودي كلها محتاجة رابط مطلق مينفعش يكون نسبي:

```bash
NEXT_PUBLIC_SITE_URL=https://your-domain.com npm run build
```

من غيره بيرجع لـ `http://localhost:3000` والبناء بيطبّع تحذير أصفر. الرجوع
للوكال هوست مقصود: لو الافتراضي كان دومين شكله حقيقي، البناء كان هينجح بصمت
والصفحات هتطلع بروابط أساسية بتشاور على موقع تاني، ومحدش هيلاحظ غير بعد ما
محركات البحث تفهرس المكان الغلط.

## النشر — Vercel

النشر بيحصل لوحده مع كل `git push` على `main`، من ربط المستودع بمشروع Vercel.
مفيش أمر تنشر بيه من الجهاز.

إعدادات المشروع على Vercel، ودول اللي بيخلّوه يشتغل:

| الإعداد | القيمة | ليه |
|---|---|---|
| Root Directory | `site` | من غيرها هيدوّر على `package.json` في جذر الريبو ويلاقي مشروع Flutter |
| Include files outside root | **مفعّلة** (الافتراضي) | `npm run build` بيشغّل `theme:check` وده بيقرا `design/palettes.json` من جذر الريبو، مستوى فوق `site/` |
| `NEXT_PUBLIC_SITE_URL` | الدومين النهائي | canonical والسايت ماب وصورة المشاركة، كلهم محتاجين رابط مطلق |

الترويسات في `site/vercel.json`: أمان (CSP، HSTS، nosniff، منع التأطير) وتخزين
مؤقت سنة للملفات اللي اسمها فيه بصمة.

**Firebase Hosting اتشال.** بلوك `hosting` اتمسح من `firebase.json` عن قصد مش
سهوًا: لو فضل موجود، أي `firebase deploy` بيعيد نشر نسخة تانية قديمة من الموقع
كله — بالصفحات القانونية — على `trademind-6222c.web.app`، ونسختين منشورتين من
سياسة خصوصية دي مشكلة حقيقية مش تفصيلة. `firebase.json` دلوقتي بينشر قواعد
Firestore بس.

> ملحوظة اتشالت مع النقلة: الاستضافة الثابتة كانت محتاجة `Content-Type:
> image/png` صراحةً على `/opengraph-image`، لأن Next بيولّدها ملف من غير
> امتداد والاستضافة بتحدد النوع من الامتداد. على Vercel بقت راوت حقيقي بيحدد
> نوعه بنفسه، فالسطر اتشال من `vercel.json`. لو نقلت لاستضافة ثابتة تاني،
> رجّعه.

## أربع حاجات لو مش عارفها هتضيّع وقتك

### ١. زرار التحميل مقفول عن قصد

`site.playStoreUrl` في `lib/site.ts` قيمته `null` لأن التطبيق لسه مانزلش على
Play. طول ما هي `null`، كل أزرار التحميل بتتحول لنص «قريبًا على Google Play»
مش لينك. أول ما التطبيق ينزل، حط الرابط في المتغيّر ده والأزرار بتشتغل لوحدها
في الأماكن التلاتة.

### ٢. صورة المشاركة والعربي — متلمسش `ArabicLine`

`app/opengraph-image.tsx` بيتولّد بـ satori، وde **بيقلب ترتيب الكلمات
العربية**: بيطلّع «ده السهم اشتريت فاكر» بدل «فاكر اشتريت السهم ده». الحروف
نفسها بتتشكّل صح — الترتيب بس هو المكسور، و`direction: rtl` مبيغيّرش حاجة.

الحل مش عكس النص (ده بيتكسر لو صلّحوا الباج)، الحل إن كل كلمة بقت عنصر flex
لوحدها والترتيب جاي من `row-reverse`. كمان satori **بيتجاهل `gap`** في الصف ده
لكن بيحترم `margin`، وبيحط حشو لكل كلمة مش متناسب مع حجم الخط — عشان كده قيم
المسافات في الملف تبان غريبة (سالبة للخط الكبير، موجبة للصغير).

**لو غيّرت أي نص أو حجم خط في الملف ده، شغّل `npm run dev` وافتح
<http://localhost:3000/opengraph-image> وبصّ عليها بعينك.** مش هتطلع مظبوطة
لوحدها.

### ٣. الخطوط متقسّمة على مكانين

- `assets/fonts/*.woff2` — اللي المتصفح بيحمّله (149KB للتلاتة)
- `assets/fonts/*.ttf` — للبناء بس، لأن satori مش بيفك ضغط woff2 (482KB)
- `public/fonts/OFL.txt` — الرخصة، لازم تفضل منشورة مع الخط

الـ TTF بره `public/` عن قصد — أي حاجة جوّه `public/` بتتنشر كما هي، فكانوا
هيبقوا نص ميجا خطوط منشورة محدش بيحمّلها. `next/font/local` بيقرا الـ woff2 من
`assets/` وقت البناء وبيحطّها في `_next/static` ببصمة.

### ٤. الألوان ليها مصدر واحد — متعدّلش `tokens.css` ولا الباليتة في Dart

كل لون في التطبيق والموقع بيتولّد من **`design/palettes.json`**:

```bash
# غيّر "active" أو أي لون في design/palettes.json، وبعدين:
npm run theme
```

بيكتب ملفين، والاتنين مكتوب عليهم DO NOT EDIT:

| | |
|---|---|
| `lib/core/theme/palettes/generated_palettes.dart` | التطبيق |
| `site/app/tokens.css` | الموقع |

`npm run build` بيشغّل `theme:check` الأول وبيرفض يكمّل لو الملفين مش متطابقين مع
المصدر — فمستحيل تنشر موقع بألوان مختلفة عن التطبيق.

**تلات قواعد مبنية في المولّد:**

1. **ألوان الفلوس مشتركة ومحميّة.** `win` و`loss` و`breakeven` عايشين في
   `semantics` بره الباليتات، وأي باليتة تحاول تعيد تعريفهم بيرفض يولّد. السبب:
   المتداول بيتعلّم إن الأخضر = ربح؛ لو تغيير الثيم قادر يعيد صبغ ده، اللون
   بيبطّل يحمل معلومة.

2. **بوابة تباين.** 28 زوج (نص على خلفية) بيتقاسوا في كل باليتة قبل ما يتكتب أي
   ملف. لو واحد تحت 4.5:1 المولّد بيقف ويقولك الرقم. الأربع باليتات اللي في
   الملف دلوقتي كلها عدّت — تلاتة منهم رسبوا أول مرة واتظبطوا.

3. **`brand` خلفية، مش نص.** لون البراند الليموني تباينه 1.15:1 على الأبيض —
   يعني نص مكتوب بيه مش هيتشاف خالص. عشان كده النص الملوّن بالبراند بياخد
   `--brand-ink` (وهو `onBrandContainer`)، والزراير بس هي اللي بتستخدم
   `bg-brand`.

### ٥. لون الـ breakeven اتغيّر في التطبيق كمان

كل التوكنز في `app/globals.css` منقولة حرفيًا من
`lib/core/theme/palettes/monochrome_palette.dart`. أول ما الموقع اتبنى، طلع إن
`--breakeven` كان `#8D6E00` بتباين 4.20:1 على سطحه — تحت حد WCAG AA (4.5:1)
لشارة بحجم 12px عريض. اتغيّر لـ `#7B6000` (5.22:1) **في الموقع وفي التطبيق**،
وباليتة الـ teal كان عندها نفس المشكلة (4.46:1) واتصلحت لـ `#9A4708`.

يعني النسختين متطابقتين دلوقتي. لو غيّرت لون في الباليتة، غيّره في الاتنين.

## علاقته بالتطبيق

- **الألوان** منقولة من باليتة التطبيق، وقاعدتها محفوظة: أبيض وأسود، واللون
  للربح والخسارة بس. مفيش زرار أخضر على الموقع كله.
- **تنسيق الأرقام** في `lib/format.ts` نسخة مطابقة من `lib/core/formatters.dart`
  — أرقام غربية بلوكيل `en` جوه نص عربي، ومكتوبة LTR عشان الإشارة السالبة
  متقعش في الناحية الغلط.
- **أرقام الموك-أب محسوبة مش مكتوبة.** `TradeCardMock` بياخد الخطة (دخول،
  استوب، كمية) ويحسب قيمة المركز والمخاطرة والربح والـ R بنفس معادلات التطبيق.
  يعني مستحيل تلاقي كارت بيعرض 3R جنب ربح مش بيقسم عليها.
